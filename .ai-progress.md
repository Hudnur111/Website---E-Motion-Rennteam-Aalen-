# AI-Wartungsprotokoll – E-Motion Rennteam Aalen Website

Dieses Dokument wird von einer autonomen Wartungsroutine gepflegt, die in
regelmäßigen Runden Audits durchführt und gezielte, sicher getestete
Verbesserungen an diesem Repository vornimmt. Jede Runde ergänzt die
Abschnitte "Erledigt" und "Nächste Schritte" unten.

## Zusammenfassung des Audits

Audit erfolgte gegen SEO, WCAG 2.1 AA, Responsive/Performance und die
bestehenden Next.js/TS/Tailwind-Konventionen, konkret gegen den Code in
`src/app/` und `src/components/` (nicht nur theoretisch).

### Kritische/hochprioritäre Funde (behoben in dieser Runde)

1. **Falscher Titel auf jeder News-/Blog-Detailseite (SEO-Bug).**
   `generateMetadata({ params })` in `src/app/news/[slug]/page.tsx` und
   `src/app/blog/[slug]/page.tsx` erwartete `params` synchron als
   `{ slug: string }`, obwohl Next.js 15+/16 `params` bei dynamischen Routen
   immer als `Promise` übergibt (die Page-Komponenten selbst `await params`
   bereits korrekt). Dadurch war `params.slug` zur Laufzeit `undefined` und
   **jede** Artikel-/News-Detailseite fiel auf den generischen Fallback-Titel
   zurück. Verifiziert per Produktionsbuild + `next start`:
   `/news/saisonstart-2026` lieferte `<title>News | E-Motion Rennteam
   Aalen</title>` statt des Artikeltitels.
2. **Doppelter Sitename in allen statischen Seitentiteln.** Jede Seite setzte
   `metadata.title` als vollen String (`"Team | E-Motion Rennteam Aalen"`),
   der zusätzlich durch das Titel-Template im Root-Layout
   (`"%s | E-Motion Rennteam Aalen"`) lief → gerenderter Titel war
   `"Team | E-Motion Rennteam Aalen | E-Motion Rennteam Aalen"`.
3. **`metadataBase` fehlte** → Next-Build-Warnung, absolute OG-/Twitter-Image-
   URLs fielen auf `http://localhost:3000` zurück.
4. **Keine `description` pro Seite** – jede Unterseite erbte exakt dieselbe
   Website-weite Meta-Description vom Root-Layout.
5. **Kein `robots.txt` / `sitemap.xml`** – beide Dateien existierten
   überhaupt nicht.
6. **Keine strukturierten Daten (JSON-LD)** für die Organisation/das Team.
7. **Lint-Fehler in `Header.tsx`** (`react-hooks/set-state-in-effect`) –
   Baseline-Verstoß gegen die eigenen Projektkonventionen.
8. **Gallerie-Lightbox (`GalleryGrid.tsx`) ohne Tastaturbedienung** –
   kein Escape-Handler, keine Pfeiltasten-Navigation, kein `role="dialog"`/
   `aria-modal`, kein Fokus-Management (WCAG 2.1.1/2.4.3/4.1.2).
9. **Kein sichtbarer, konsistenter Fokusindikator** für interaktive Elemente
   über die Browser-Standardwerte hinaus (WCAG 2.4.7); Formular-Inputs
   nutzten `outline-none` ohne vollwertigen Ersatz.
10. **Keine `prefers-reduced-motion`-Unterstützung**, obwohl Framer Motion an
    sehr vielen Stellen eingesetzt wird (Hero, Seitenübergänge, Reveals,
    Counter, Nav-Underline, …).
11. **Kein Skip-Link / kein `id`-Ziel für Hauptinhalt**, mehrere `<nav>`-
    Landmarks ohne unterscheidbares `aria-label`.

### Weitere Funde (dokumentiert, in dieser Runde nicht angefasst – siehe
"Nächste Schritte")

- Farbkontrast wurde nur stichprobenartig geprüft (dunkles Theme,
  `--muted: #9aa0b4` auf `--background: #06070d` wirkt unkritisch), aber kein
  systematischer Kontrast-Check aller Text/Hintergrund-Kombinationen
  (z. B. `text-muted/80` auf hellen Sponsor-Badges) wurde durchgeführt.
- Kein automatisierter Accessibility-Scan (z. B. axe-core/Lighthouse CI) ist
  eingerichtet.
- Bundle-Größe/Code-Splitting wurde nicht vermessen (kein
  `next build --profile`/Bundle-Analyzer eingerichtet).
- Kein `manifest.json` / PWA-Icons über `favicon.ico`/`icon.svg` hinaus.
- Die Formular-Komponenten (`ContactForm`, `SponsorForm`,
  `MemberApplicationForm`, `NewsletterForm`) wurden nicht auf serverseitige
  Validierung/echten Versand geprüft (nur oberflächlich betrachtet).
- `alt`-Texte sind überall vorhanden und sinnvoll (kein Fund hier), aber es
  wurde nicht geprüft, ob rein dekorative Bilder ggf. `alt=""` bräuchten.
- Der produktive Domainname stand **nirgends** im Repo (kein `vercel.json`,
  keine `.env.local.example`, kein `NEXT_PUBLIC_SITE_URL`). Für
  `metadataBase`, `sitemap.xml`, `robots.txt` und die JSON-LD-URLs wurde
  `https://emotion-rennteam.de` als bestbegründete Annahme verwendet
  (abgeleitet aus der Kontakt-E-Mail-Domain `emotion-rennteam.de`). **Bitte
  in der Deployment-Umgebung `NEXT_PUBLIC_SITE_URL` setzen**, falls die
  echte Produktions-URL abweicht (siehe `src/lib/site.ts`).

## Erledigt in dieser Runde

Alle Änderungen sind in kleinen, konventionellen Commits auf
`claude/keen-mayer-xe0pw3` gelandet (siehe `git log`):

1. `fix(header): avoid setState-in-effect cascading renders on route change`
   – Baseline-Lint-Fehler behoben, per React-Doku-Pattern
   ("adjusting state during render").
2. `feat(seo): add metadataBase, canonical URLs, Organization JSON-LD,
   robots.txt and sitemap.xml` – neue `src/lib/site.ts`,
   `src/app/robots.ts`, `src/app/sitemap.ts` (inkl. aller News-/Blog-Slugs).
3. `a11y: add skip-to-content link, nav landmarks, and reduced-motion
   support` – Skip-Link, `aria-label` auf beiden `<nav>`s, neue
   `MotionProvider`-Komponente (`MotionConfig reducedMotion="user"`)
   app-weit im Root-Layout.
4. `a11y: make the gallery lightbox keyboard-accessible` – `role="dialog"`,
   `aria-modal`, Escape/Pfeiltasten, Fokus-Management in `GalleryGrid.tsx`.
5. `a11y: add a global focus-visible ring and honor reduced-motion for
   smooth scroll` – globales CSS in `globals.css`.
6. `fix(seo): stop duplicating the site name in page titles, add meta
   descriptions` – alle 12 statischen Seiten überarbeitet.
7. `fix(seo): await params in generateMetadata for blog/news detail pages`
   – der zentrale SEO-Bug (siehe oben), plus Open-Graph-Artikel-Metadaten.
8. `test: add Vitest + React Testing Library and initial unit/component
   tests` – Test-Setup + Tests für `content.ts` (Sortier-Invarianten) und
   `GalleryGrid` (die neuen A11y-Fixes).

**Warum Vitest + React Testing Library:** kein Test-Framework existierte.
Vitest wurde gewählt, weil es nativ mit TypeScript/ESM funktioniert, sich
minimal-invasiv einrichten lässt (eine `vitest.config.ts`, kein Babel-Setup
nötig) und der De-facto-Standard für Vite-/Next.js-nahe React-Projekte ist;
React Testing Library ist der Standard für komponentenorientierte Tests in
diesem Ökosystem. Beide sind reine Dev-Dependencies ohne Auswirkung auf den
Produktions-Bundle.
