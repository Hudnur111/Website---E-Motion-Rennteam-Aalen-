### Critical open issue — NOT fixed, needs a decision
**`ContactForm.tsx` and `NewsletterForm.tsx` do not actually submit
anywhere.** Both `handleSubmit` handlers just call
`e.preventDefault()`, fake a 600ms "sending" delay, then show a
success message — no `fetch`, no API route, no mailto, nothing. Every
sponsor inquiry, press request, job application, and newsletter
signup submitted through the site is silently discarded while the
visitor is told it went through. This is a real business-impact bug,
not a style nit.

Not fixed this session because a correct fix needs an infrastructure
decision I can't make unilaterally: which email delivery provider
(Resend, Postmark, SMTP via a hosting-provided relay, a serverless
form service like Formspree, etc.) and its API credentials as env
vars. Recommend the next session (or a human) picks a provider, then:
- add `src/app/api/contact/route.ts` and `src/app/api/newsletter/route.ts`
  (or equivalent) doing server-side validation + the actual send/store,
- wire the two form components to `fetch` those routes and handle
  real error states (not just sending/sent),
- add the provider's API key to the deployment's env vars (never commit it).
